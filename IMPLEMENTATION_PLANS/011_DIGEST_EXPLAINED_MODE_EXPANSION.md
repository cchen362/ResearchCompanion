## Root Cause Analysis

### Problem 1: Questions for Doctor & Warning Signs Never Show

The database columns, frontend types, `transformToFrontend`, SQL SELECT aliases, and UI rendering **all exist and work correctly**. But the AI never generates the data because of **3 interdependent gaps**:

| Gap | File | Issue |
|-----|------|-------|
| **1. AI JSON Schema** | `backend/src/schemas/digest.schema.ts` | `questionsForDoctor` and `warningSigns` are NOT in `digestJSONSchema` properties, AND `additionalProperties: false` blocks Claude from returning unknown fields |
| **2. AI Return Value** | `backend/src/services/ai.service.ts` | Lines 640-663 don't extract `questionsForDoctor` or `warningSigns` from `digestData` |
| **3. CRUD Zod Schema** | `backend/src/routes/digests.crud.routes.ts` | `CreateDigestSchema` is missing `key_takeaways`, `layman_summary`, `questions_for_doctor`, `warning_signs` — Zod silently strips them on frontend-initiated saves |

**Result**: DB always gets empty arrays `[]` → UI conditionals `length > 0` hide the sections.

### Problem 2: 5 Sections Don't Support Explained Mode

Only `featuredDiscovery` and `topFindings` have dual `{technical, explained}` content. These sections are plain text:

| Section | Current Type | What It Needs |
|---------|-------------|---------------|
| Key Takeaways | `string[]` | `DualModeText[]` |
| Breakthroughs | `{title: string, description: string}` | `{title: DualModeText, description: DualModeText}` |
| Contradictions | `{topic: string, claim: string, explanation: string}` | Dual-mode for `topic`, `claim`, `explanation` |
| Questions for Doctor | `string[]` (always empty - never generated!) | `DualModeText[]` + fix pipeline gaps |
| Warning Signs | `string[]` (always empty - never generated!) | `DualModeText[]` + fix pipeline gaps |

### Design: DualModeText

```typescript
export interface DualModeText {
  technical: string;
  explained: string;
}
```

**No backward compatibility needed** — user confirmed they can delete old topics and regenerate fresh digests.

**No database migration needed** — all affected fields are JSONB columns that accept any valid JSON structure.

## Pipeline Layers Reference

Every field change must flow through ALL 6 layers:

```
Layer 1: AI JSON Schema          → digestJSONSchema in digest.schema.ts (what Claude CAN return)
Layer 2: AI Zod Validation       → SmartDigestSchema in digest.schema.ts (validates Claude output)
Layer 3: AI Prompt + Return      → ai.service.ts (what Claude is ASKED to return + what we extract)
Layer 4: CRUD Zod Schema         → CreateDigestSchema in digests.crud.routes.ts (frontend save validation)
Layer 5: Frontend Types + Service → types/index.ts + digest.service.ts (TypeScript types + transforms)
Layer 6: UI Rendering            → DigestCard.tsx (what users see)
```

The background processor INSERT (`digest-processor.service.ts`) already writes `questionsForDoctor` and `warningSigns` using `JSON.stringify((digest as any).questionsForDoctor || [])` at lines 264-265. It also uses `JSON.stringify` for `key_takeaways`, `breakthroughs`, `contradictions`. Since these are all `JSON.stringify` of the AI return value, the structural change from strings to DualModeText objects flows through automatically. **No changes needed to the background processor.**

### AI Returns questionsForDoctor/warningSigns as Empty Arrays

**Check 1**: Verify `digestJSONSchema` has the properties:
```bash
docker exec medical-companion cat /app/dist/schemas/digest.schema.js | grep questionsForDoctor
```
If no output → old build cached. Force rebuild: `docker compose down && docker compose up -d --build --no-cache`

**Check 2**: The AI may not generate these for every topic. Try with a condition that has clear treatment implications (e.g., diabetes, hypertension).

### Zod Validation Fails After Schema Change

**Symptom**: Logs show "Zod validation failed" with issues about `title` expecting object but receiving string.

**Cause**: This means the AI returned old-format data (plain strings). The AI prompt update may not have taken effect.

**Fix**: Verify the system prompt includes the dual-mode instructions. Check: `docker exec medical-companion cat /app/dist/services/ai.service.js | grep "DUAL-MODE"`

### TypeScript Build Errors in Export Service

**Symptom**: `npm run build` fails with errors in `export.service.ts` referencing `breakthrough.title` as string.

**Fix**: Find the references and update to `breakthrough.title.technical` (export service should use technical mode by default). Or if the export service generates both modes, handle accordingly.

### Token Truncation

**Symptom**: AI output is cut off, missing fields at the end.

**Fix**: Increase `max_tokens` from 8000 to 12000 in `ai.service.ts` line 406.
